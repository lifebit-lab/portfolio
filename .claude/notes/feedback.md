## 2026-10-10 ポートフォリオ全面改修（全セクション）

### よかった点

- **背景をライブラリなしで作ったこと** — Three.js（約170KB）を入れずに、素のWebGL1のフラグメントシェーダー11KBで「光る実験体」を実現できた。結果としてファーストビューが軽く、本番実測でLCP 0.7秒（デスクトップ）・1.0秒（モバイル）。重いライブラリを入れていたらこの数字は出なかった。
- **背景をセクションに連動させたこと** — 球の位置・大きさ・色相・不透明度を `SCENES` の表として `js/main.js` に持たせ、IntersectionObserverで切り替える構成にした。セクションごとの演出を1箇所で調整でき、「スクロールするたび世界が変わる」感覚が低コストで出た。
- **作品ごとに構図を変えたこと** — `work--right` / `--left` / `--wide` / `--phone` / `--feature` の5種を交互に並べたことで、10件あっても一覧の退屈さが出なかった。Aurora Memoriaだけ全幅の特集枠にして、作品の格の違いを構図で表せた。
- **作品の見せ方を内容に合わせたこと** — スクショを貼るだけで終わらせず、Okuribaは傾いたお便りカード2枚、aura.はオーラカード、哲学は実在する概念チップ、バリアフリーはスマホ枠にした。「何をするアプリか」が画像を見ただけで伝わる。
- **状態バッジを4種類に分けたこと** — LIVE / DEMO / PAUSED / COMING SOON。色と点の形を変えたので、一覧をスクロールするだけで公開状況が把握できる。誠実さがそのままデザインの情報量になった。
- **既存機能を捨てずに格納したこと** — 使い方アコーディオンとGiscusを `<details>` の中にまとめ、世界観を壊さずに機能を全部残せた。

### 微妙だった点・改善点

- **「文字を暗く置いて、スクロールで点灯させる」演出がコントラスト基準と衝突した** — イントロの行を `opacity: .14` から始めたところ、Lighthouseで4件のコントラスト違反。暗い初期状態も「表示されているテキスト」として評価されるため。**理由**: 出現演出の初期状態は、演出前であってもアクセシビリティの判定対象になる。opacityで暗くする演出は、暗い側の値が基準を満たす範囲（白文字なら .6 以上、本文サイズなら .72 以上）でしか使えない。transform や clip-path による出現なら、この制約を受けない。
- **巨大タイポはモバイルでサイズ区分が変わる** — `line--small` はデスクトップでは59px（大きいテキスト＝3:1でよい）だが、モバイルでは18pxになり4.5:1が必要になった。**理由**: `clamp()` で可変にした文字は、画面幅によってコントラストの合格ラインが切り替わる。デスクトップだけで検証すると見落とす。
- **固定配置のUIが本文に重なった** — 右端のセクションインジケーターが、アクティブ時にラベルを出す設計だったため、本文の上に文字が乗った。**理由**: 画面端の装飾UIは「常時表示の状態」で本文と干渉しないかを、全セクションでスクロールして確認する必要がある。今回はホバー・フォーカス時のみラベルを出す方式に変更して解決した。
- **グリッド内の要素が最小幅を押し広げた** — Coming Soonカードがスマホで横スクロールを発生させた。**理由**: グリッドアイテムの `min-width` は `auto` が既定のため、中の長い要素（等幅フォントのラベルなど）がトラックを広げる。`minmax(0, 1fr)` と `min-width: 0` を明示する癖をつける。
- **Webフォントが描画を2.16秒ブロックしていた** — `<link rel="stylesheet">` で3書体を読んでいたため。`media="print"` + `onload` の非ブロック読み込み（noscript併記）に変えてPerformanceが73→100になった。**理由**: `display=swap` を付けても、スタイルシート自体の取得は描画をブロックする。swapはフォントの適用方法の話で、読み込みの話ではない。
- **デコイのリンクにカーソル演出を付けた設計** — ビジュアル全体を `<a tabindex="-1" aria-hidden="true">` にして、本文側に実リンクを置いた。見た目と操作性は両立できたが、同じ遷移先のリンクがDOM上に2つある構成なので、作品を増やすときに片方だけ更新する事故が起きやすい。将来リンクをデータ化するなら統合したい。

### DESIGN.md への反映事項

以下は今回 `.claude/DESIGN.md` に反映済み。

- 出現演出でopacityを使う場合、暗い側の初期値は白文字 `.6` / 本文サイズ `.72` を下限とする
- Shadowは使わない（暗い画面では発光とコントラストで階層を作る）
- ライムは「触れる場所・今ここ」、バイオレットは「光・奥行き」だけに限定する
- WebGLキャンバスに文字やナビゲーションを描かない
- 同時に動く主役は1つ。セクションごとに演出の種類を変える

さらに、今回の実測で見つかった落とし穴は `DESIGN.md` の「検証の観点」としてチェックリスト化した（`clamp()` の最小サイズ側でのコントラスト、固定UIと本文の干渉、グリッドの `min-width`、Webフォントの非ブロック読み込みなど）。
